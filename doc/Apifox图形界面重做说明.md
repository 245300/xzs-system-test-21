## 2. 操作步骤（全部在 GUI 内完成）

1. **新建项目**：首页右上角 `+ 新建项目` → 选"以可视化界面维护接口" → 项目名 → 创建。
2. **导入契约**：项目设置 → 数据管理 → 导入数据 → `OpenAPI/Swagger` → 上传文件 →
   选 `doc/openapi.json` → 预览勾选 → 导入到"创建新模块" → **导入成功：接口/文档 11 个**。
3. **配环境**：右上角环境下拉 → 管理环境 → 测试环境 → 把模块的**前置 URL** 设为
   `http://127.0.0.1:8065` → 保存。
4. **建场景**：自动化测试 → 新建场景用例 → 名称 `场景一：管理端登录-首页接口测试` →
   添加步骤 → 从接口导入 → 勾选 4 个接口 → 添加。
5. **调步骤**：逐个步骤把 URL 改成绝对地址（见第 4 节坑 2），并关闭"校验响应"（见坑 3）。
6. **运行**：运行环境选"测试环境" → 运行。

## 4. 图形界面里踩到的三个坑（与 CLI 完全不同）

1. **"新建项目"入口在首页右侧**。个人团队首页只有项目卡片时容易以为没有入口；
   实际按钮在团队项目页右上角，`Ctrl+N` 和深链接都无效。
2. **环境的前置 URL 要配到"模块"那一行**。Apifox 把导入的接口挂在新建模块下，
   只改"默认模块"的前置 URL 不起作用：请求会被拼成 `http://api/admin/...`，
   运行报 `Invalid URI "http://api/admin/dashboard/index"`。
   两个办法：模块行单独填一遍并**失焦提交后保存**；或者直接把步骤 URL 写成绝对地址（本次两者都做了）。
3. **"校验响应"会和没有定义 Body 的契约打架**。OpenAPI 里这些 POST 的 200 响应没写 `content`，
   Apifox 的契约校验于是判定"该响应不应该有 Body"，而实际返回 `{"code":..,"message":..}`，
   4 个步骤全被判失败（HTTP 明明是 200）。关掉逐步骤的"校验响应"后恢复正常。
   真实断言应写在"后置操作 → 断言"里；本次断言仍以 CLI 集合（69 条）为准。
