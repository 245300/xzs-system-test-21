### 4.3 接口测试（Apifox，用户指定）

1. 在 Apifox 桌面版新建项目「软件测试实验8-学之思管理端接口」，环境前置 URL `http://localhost:8065`，公共 Header 与 Cookie 变量。
2. 建 3 个场景（目录即场景），每个场景第一步必须是**未登录反向用例**，随后登录并保存 `JSESSIONID`：
   - 场景1 管理端登录-首页：8 个请求（未登录 401、错误密码、正确登录、首页统计、学科分布、待办、系统信息、退出后再访问 401）；

4. 用 Apifox「运行」生成 HTML 报告并截图；随后导出 **Apifox CLI 集合 JSON** 到 `api/`（3 个文件）。
5. **格式关卡**：导出文件必须含 `apifoxCli: "1.1"`、每步 `metaInfo.type=http`、`event` 断言；先用 `apifox run` CLI 2.2.9 本地跑通，再交客户端评分。GUI 是源，CLI JSON 是评分产物，两者同源同版本。

### 4.4 性能测试（JMeter + 插件 + ServerAgent）

**录制方式（附录2 正规流程）**：JMeter GUI 添加 HTTP(S) Test Script Recorder（端口 8888）→ Chrome 以 `--proxy-server=127.0.0.1:8888` 启动 → 手工操作管理端三条业务 → 录制到目标控制器 → 过滤静态资源 → 整理脚本。本地 8065 为 HTTP，无需安装证书。

**脚本设计**：

| 线程组 | 线程 | 循环 | 业务 | 采样器 |
|---|---:|---:|---|---|
| 线程组1-用户管理新增学生 | 3 | 2 | 管理端登录→用户管理→学生列表→新增学生A→新增学生B→列表复核 | 5 |
| 线程组2-卷题管理新增题目 | 1 | 3 | 登录→题目列表→新增题目→题目列表复核 | 4 |
| 线程组3-试卷管理新增试卷 | 2 | 2 | 登录→试卷列表→新增试卷→试卷复核（卷题管理查询） | 4 |

- 合计 13 个 HTTP 采样器、3 个事务控制器、3 个 CSV 数据集（学生姓名/题目内容/试卷名，各 3 行）、1 个公共 HTTP 信息头管理器、Cookie 管理器、聚合报告 + 察看结果树。
- 每个采样器至少 2 个响应断言：HTTP 200 + 业务码 `code=1`；`HTTPSampler.domain` 必须写死 `localhost`。
- 成功请求预估 ≥ 58（3×2×5 + 1×3×4 + 2×2×4），错误 0，响应 < 50000 ms。
- 写操作使用唯一前缀（如 `性能测试学生_1113_A`），避免重复运行主键冲突；跑完保留数据并在报告中说明测试数据隔离方式。

**服务器性能（指导书指标）**：安装 JMeter Plugins Manager → PerfMon Metrics Collector；解压并启动 ServerAgent-2.2.3（`startAgent.bat`，端口 4444）；压测同时采集 CPU、内存、磁盘，保存 `report/jmeter/server-metrics.csv` 并生成曲线截图。若插件/Agent 下载受网络限制，降级用 Windows `typeperf` 采集并在报告中说明替代原因，绝不编造数据。

**产出**：`jmeter/xzs_admin_perf.jmx`、`perf_data.csv`、`report/jmeter/result.jtl`、`report/jmeter/html/index.html`、`server-metrics.csv`、聚合统计 `statistics.json`。
