# 实验题目 : 学之思系统测试

## 被测系统说明

> 本题要求学生以“学之思系统”为被测对象，围绕在线学习、考试答题与后台管理等典型业务流程开展黑盒手工功能测试。学生应结合学生端、教师端或管理员端等主要角色，选择核心业务场景设计测试用例并完成执行记录。
>
> 地址：\[http://localhost:8065/admin/index.html](http://localhost:8065/admin/index.html)  
账号：admin / 123456
>
> 建议测试内容：登录注册、学生端答题、试卷管理、题库管理、考试管理、成绩统计、用户管理、教师端/管理员端管理
>

## 提交测试内容：

1. 手工测试
2. Web自动化测试
3. Web API 接口测试
4. JMeter 性能测试
5. 测试报告

## 手工测试

### 建议测试模块

> 登录注册、学生考试、试卷练习、错题管理、成绩查询、题目管理、用户管理
>

### 测试任务要求

* 根据功能性测试技术设计测试用例，建议综合使用等价类划分法、边界值分析法、场景法、错误推测法等方法。
* 至少选择并覆盖 3 个核心功能模块；每个模块应尽量包含正常场景和异常场景，避免只记录单一成功路径。
* 测试用例应包含用例编号、功能模块、测试标题、前置条件、测试步骤、测试数据、预期结果等内容。
* 按照设计的测试用例集完成手工执行，并记录实际结果、执行状态、执行时间、测试版本或测试环境等信息。
* 根据测试执行情况记录缺陷（BUG），缺陷信息应尽量包含缺陷编号、所属模块、复现步骤、实际结果、预期结果、严重程度或优先级。
* 最终提交内容一般为 Excel 手工测试记录，可包含测试用例表、测试执行记录、缺陷记录、截图说明和数据统计分析等内容。

### 得分标准

将从以下几个方面进行评分：

* 测试过程记录
* 测试用例规范性
* 缺陷记录规范性
* 图文配合效果
* 报告数据准确性

### 说明

本题重点考查学生是否能够围绕指定 Web 系统完成规范的手工功能测试设计与执行。评分时将关注测试记录是否真实、字段是否完整、模块覆盖是否充分、缺陷描述是否清楚，以及截图、说明和统计数据是否能够支撑测试结论。

## 性能测试

### 测试场景

* 登录网页，点击用户管理，在学生列表中添加至少2名学生
* 登录网页，点击卷题管理，在题目列表中自定义题目信息
* 登录网页，点击卷题管理，在试卷列表中添加试卷

### 测试要求

* 设置线程数量线程数：1-5，循环次数：2-3；
* 至少包含3个线程组；
* 脚本包括断言验证， 对关键接口添加响应断言，至少验证：HTTP状态码为200；
* 至少包含1个事务；
* HTTP采样器数量不少于10（可包含登录、查询、操作等不同接口），必须包含查询卷题管理的测试；
* 包含一个HTTP头管理器；
* 必须使用监听器包含聚合报告和查看结果树；
* 成功请求数量不少于20；
* 响应时间应小于50000ms;

## Web系统综合测试报告

### 提交文件要求

> 本题要求学生针对“学之思系统”完成一份综合测试报告。报告应围绕该系统的实际业务流程展开，体现功能测试、Web自动化测试、性能测试、接口测试等综合测试能力。学生最终提交 \*\*Markdown（.md）格式综合测试报告\*\*。
>

### 测试报告要求

* 报告必须明确说明被测系统为“学之思系统”，并说明测试目标、测试范围、测试环境和测试工具。
* 功能测试部分应覆盖不少于3个核心模块，包含测试用例、测试步骤、预期结果、实际结果、缺陷记录或结果总结。
* Web自动化测试部分建议使用 Selenium IDE、Selenium WebDriver 或等价工具，Markdown报告中应体现脚本、关键代码、录制过程、执行截图说明、日志或运行结果。
* 性能测试部分建议使用 JMeter，可结合 HAR 转 JMX 工具或 BlazeMeter Converter 等方式生成脚本，Markdown报告中应体现并发数、请求场景、响应时间、吞吐量、错误率、聚合报告或图表说明。
* 接口测试部分建议使用 Apifox、Postman、curl 或等价工具，Markdown报告中应体现接口URL、请求方法、请求参数、状态码、JSON响应、断言结果或结果分析。
* 报告应包含测试结论与改进建议，并尽量使用 Markdown 表格、图片引用、截图说明、日志、代码块、接口响应或数据结果支撑结论。
* 若报告中引用图片或截图，应保证图片链接、相对路径或截图说明能够与正文内容对应；不得只写工具名称而没有测试过程或结果证据。

### 得分标准

将从以下几个方面进行评分：

* 功能测试内容与证据
* Web自动化测试证据
* 性能测试证据
* 接口测试证据
* 报告规范性、结论与真实性

  本题评分关注学生是否在 `.md` 格式报告中体现真实测试过程和基本证据。只要 Markdown 报告中能够读取到清楚的测试模块、测试步骤、工具使用过程、运行结果和结论，即可按完成质量评分；不要求工具截图、代码和数据达到工业级完整程度，但不得虚构报告中没有出现的测试数据、截图数量、接口数量或缺陷数量。
